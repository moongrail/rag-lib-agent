# ADR 0001 — PostgreSQL + pgvector как векторное хранилище

**Статус:** Принято

**Контекст.** Нужно хранилище векторов для RAG. Варианты: выделенные vector-DB
(Qdrant, Milvus, Chroma, Elasticsearch) против PostgreSQL с расширением `pgvector`.

**Решение.** Использовать PostgreSQL + `pgvector`.

**Последствия.**
- Единое хранилище для векторов и метаданных документов → одна backup/restore, один пул
  соединений, транзакционная консистентность между `rag_embeddings` и `documents`.
- Привычная для enterprise эксплуатация.
- HYBRID-поиск (вектор + FTS) встроен через `SearchMode.HYBRID` + RRF.
- Компромисс: чистая векторная пропускная способность ниже, чем у выделенного движка;
  смягчается IVFFlat/HNSW индексом (`useIndex`) для больших корпусов.
